Describes an information system by identifying and using objects

An object represents a real person, place or event in a data flow diagram for if you where to to purchase something at the store the receipt is an object, the cashier is an object and you are an object.

An attribute are characteristics that describe the object such as names, colors, or integer values of things

A method is a function that is defined within the object that does a task when its method called or Messaged. An example of a method is doing the dishes that would have multiple steps within that define how the tasks gets done, walking the dog would be another task that could be called or going to work is another method that takes a number of steps to get to the desired output.

Encapsulation works by allowing us to bundle our system into its own class or object so that it may act independently from the rest of the system which allows easier maintenance because what happens to one object or class wont necessarily affect the rest.

A class is the blueprint representation of an object, an object derived from a parent class is called a subclass and a super class is the highest class blueprint we can call a parent class for example Vehicle -> Car -> SuperCar this way we can see that it goes SuperClass -> Class -> Subclass

Inheritance works by deriving functionalities from a higher level "parent" class so that you may have varying functionalities from different objects using the same parent classes methods.



A use case represents the steps in a specific business function or process a use case diagram is a visual summary of several related use cases within a system or subsystem

Its important to use a modeling tool because you need to model the actual processes that have to be performed within the diagram that was used its can be seen as a step in creating a logical model because you need to know the flow of data and how its going to where it needs to be.
