A logical model shows how a system should work regardless of how its implemented while a physical model describes how the system would actually be built.

A data flow diagram uses symbols to show how a system transforms input data into useful information.



- Draw a diagram so that it fits on one page
- Use the name of the information system as the process name in the context diagram
- Use unique names for each set of symbols
- Do not cross lines
- Provide a unique name and reference number for each process
- Ensure that the model is accurate, easy to understand and meets the needs of its users

A context diagram is a top level overview of an information system that displays the systems boundaries and scope, while a process 0 is the entire information system or "black box" that contain all of the processes that happen.

Data Store

You level a data flow diagram by using increasingly detailed diagrams until you reach a systems primitive functions

You balance a diagram by keeping as much as the input and output data flow paths of the parent diagram  in the child diagram

A data element is the smallest piece of data that has meaning in an information system which includes the names of all the data elements in a system, their meaning in the data system and the abbreviations or codes that represent them.
